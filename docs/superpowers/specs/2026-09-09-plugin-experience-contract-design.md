# 内置插件统一体验契约设计

## 背景

DSH Desktop 当前包含 13 个 Yootun Client 插件、桌面原生设置界面和多个 MCP/API 能力入口。插件已经共享 Desktop 主题别名和基础互斥机制，但每个插件仍分别实现页头、图标按钮、数据状态、动作状态、加载态、空态和错误恢复，造成同类操作在不同页面上具有不同的尺寸、文案、颜色和锁定范围。

## 目标

- 让所有内置插件使用一致的页头、关闭/刷新操作、间距和响应式规则。
- 让 MCP 能力状态和本地 API 数据状态使用同一套可识别的语义。
- 让需要人工确认的动作与适配器执行结果具有一致的生命周期表达。
- 保留每个插件适合业务的内容布局，不把看板、表格、知识图谱和工作台强行改成同一种结构。
- 通过自动门禁、组件契约测试和浏览器截图阻止体验再次漂移。

## 非目标

- 不更改 MCP 服务端协议、认证方式或工具名称。
- 不把独立插件合并成单一运行时包。
- 不改变业务 API 的权限、持久化、幂等或审计行为。
- 不覆盖用户已有的未提交截图变化。

## 体验契约

### Shell

每个可关闭插件都使用 `role="dialog"`、`aria-modal="true"` 和唯一标题；打开时记录触发控件，关闭后恢复焦点，并支持 Escape。页头采用 72px 的桌面基线、移动端 64px 基线，左右内边距使用 16px/24px，图标按钮为 36px 方形、6px 圆角。刷新按钮仅在当前请求或写操作影响同一数据源时禁用，关闭按钮始终保持可用。

### 数据状态

本地 API 和 MCP 聚合结果统一映射为：

- `ready`：数据可用，允许相关操作。
- `loading`：首次加载或无旧数据的请求中，显示结构化加载态。
- `empty`：请求成功但当前范围无数据，显示范围上下文和下一步动作。
- `degraded`：部分来源可用，明确列出受影响来源。
- `unavailable`：能力或来源未接入，显示来源、原因和重试/配置动作。
- `error`：请求或解析失败，显示错误播报和重试动作。

状态不得只依赖颜色；必须同时包含文字或图标。缺少字段不得静默显示为零。

### 动作状态

需要外部适配器的动作统一使用：`awaiting_confirmation`、`confirmed_pending_adapter`、`succeeded`、`failed`、`requires_user_login`、`dismissed`。确认后立即反馈“已受理/等待适配器”，执行中的同一动作和相关刷新控件锁定，其他导航和关闭操作保持可用。失败必须保留可重试入口，并将适配器原因映射为用户可读文案。

### 视觉令牌

插件只使用 Desktop 主题别名，不写固定的语义颜色。主操作使用 `--dsw-alias-button-primary-fill` 与 `--dsw-alias-label-primary-foreground`；成功、警告、错误分别使用对应 `state-*` 别名。内容面板最多使用 8px 圆角，避免嵌套卡片和阴影堆叠。统一使用 4px 间距倍数，并在 320px、768px、1024px、1440px 视口验证无横向溢出。

## 实现边界

第一阶段在根仓库增加跨插件 UX 门禁，抽取可由静态检查验证的 shell、状态、主题和异步交互规则；同时统一最常用的页头和根级错误/不可用状态。门禁只读取插件源码和构建产物，不改变运行时依赖图。

第二阶段按风险分组改造插件：数据面板（dashboard、finops、daily-report、audit）、工作台（sales、lead-discovery、recruiter、supply-watch、content-command）、知识与媒体（knowledge、retrofit、xhs-operation）。每组完成后立即构建、单测和浏览器截图回归。

第三阶段对 MCP/API 映射、状态来源和动作审计做端到端检查，确认界面状态与服务端实际响应一致，尤其覆盖来源不可用、部分成功、等待确认、登录失效和重试场景。

## 测试与验收

- `corepack pnpm check:ux` 检查所有 13 个插件和原生访问界面的主题别名、状态播报、Escape、焦点恢复、请求锁和安全请求选项。
- 各插件自身 `check`、桌面 `typecheck` 和相关单元测试必须通过。
- 浏览器测试在 390px 与 1440px 截图，覆盖首次加载、空数据、来源不可用、写操作忙碌、确认和失败恢复；控制台无 error/warning，页面无横向滚动。
- 可访问性树包含对话框名称、按钮名称、状态播报和合理的标题层级。
- 根目录 `corepack pnpm check` 作为最终门禁；已有与本任务无关的环境失败必须单独记录，不得被误报为体验通过。

## 分阶段提交

每个阶段保持小而可审查的提交，使用中文 Conventional Commits，并在提交后推送到 `origin`。规格提交与行为提交分离；现有工作树中的截图变化不纳入本设计提交。
