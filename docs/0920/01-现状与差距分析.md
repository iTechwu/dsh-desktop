## 3. 关键事实（决定方案走向）

1. **SSO 侧没有、也不需要有 model_api_key 概念**（全仓库 grep 无结果）。key 的权威方是 models——0901 治理文档已定义为"用户登录 SSO → Models Key 管理 API（携带 SSO 会话）→ Models 向 SSO 校验 → 签发只展示一次的 key"。本方案完全沿用该权威流程。
2. **models 的 `@@unique([keyOwnerType, ownerExternalId])` 天然支持幂等签发**：`keyOwnerType=human` + `ownerExternalId=ssoSub` 即可实现"同一用户永远拿到同一把 key"。
3. **MCP 鉴权不建议改为 SSO JWT 直连**（models 报告 §改造点）：需改 guard、新增"用户默认团队"解析、修限流 keyGenerator、补归因列，且按 key 聚合的报表会漏计。保留 key 形态 = 零改动继承全部统计/配额/绑定。
4. **docker-helm/nginx 零改动**：models 公网入口 `ixicai.cn/api/*` 已全量转发 models-api（`nginx/ixicai.cn.https.conf`），新端点做在 models 内即可；SSO 域名 `sso.ixicai.cn` 的 OIDC 端点已发布（`JWKS_URI=https://sso.ixicai.cn/api/.well-known/jwks.json`）。
5. **桌面端 Host 路由有 connection cookie 栅栏**，外部浏览器 302 无法直接打进来 → loopback 回调监听必须是独立的一次性监听器（不复用 Host webServer），见 02 文档 §3。
6. **knowledge 的 `team.<groupId>` spaceKey 文法桌面端已内置**（`dsh-plugin-desktop` knowledge wrapper 正则 `^team\.[a-zA-Z0-9_.-]{1,160}$`），飞书部门 ID 可直接作为 groupId，客户端零改动。
7. **桌面端能力复选框 + `enabledPlugins` → `dofe-managed` ROUTES 装载门**就是现成的插件权限执行点，服务端下发 entitlements 后只需替换数据来源，`normalizeDofePluginIds` 保留为最终防线。
